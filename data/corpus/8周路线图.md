# 8 周路线图（7 天只是第 0 周）

前提是直说：**第 0 周每天 45 分钟；第 1 周起每天约 2 小时**。若无法提到 2 小时，请把终点从「1–2 个月」改成「3–4 个月」，比自欺要好。

## 第 0 周（7 天 × 45 min）：启动周
[[Day1_岗位反推与项目骨架]] → [[Day7_简历与面试弹药]]。
交付：1 个公网可访问、有评测数据、有容错的手写 RAG + 工具调用项目。
验收：[[目标与验收标准]] 第 3 节阶段门槛全勾。

## 第 1–2 周：把 Demo 变成工程
- 用 LangGraph（或一个 Agent 框架）重写 Day5 的分发循环，补：多轮状态、条件分支、超时与重试、流式输出
- **为什么这时才上框架**：先手写再上框架，你才说得清「框架替我做了什么」，这正是面试官追问的点
- 接日志埋点（记录每次检索命中、token 消耗、耗时、失败原因）
- 建 CI：提交即跑评测脚本，指标下降就报警
- 产出：README 更新架构图；写 1 篇复盘《我手写的循环和 LangGraph 差在哪》

## 第 3–4 周：第二个项目，贴近真实业务
- 选题标准：**有真实约束**（权限隔离 / 多租户 / 数据更新 / 成本上限），不要再做通用问答机器人
- 例：带文档权限过滤的企业知识库，或能查订单状态并拒答越权问题的客服 Agent
- 必做：权限或安全边界、代价控制（缓存 / 限流 / token 预算）、失败降级
- 产出：第二个公开仓库 + Demo；1 篇技术复盘（写一次优化失败的归因）

## 第 5–6 周：补工程基本面 + 稳定部署
- 并发、超时、重试、幂等、缓存、日志与可观测；Docker + 一条最小 CI/CD
- Python 工程题 30 道（只刷与异步、数据结构、接口设计相关的，不刷算法竞赛题）
- 把两个 Demo 稳定运行一周，确认冷启动、超时、额度耗尽都不崩
- 产出：README 的「已知限制」章节——**敢写限制比堆功能更像工程师**

## 第 7–8 周：被市场验证
- 简历定稿：2 条量化项目（见 [[简历项目描述模板]]），把 2 个仓库链接放首屏
- 投 ≥ 30 份，按 JD 微调关键词，不海投同一版
- 至少 5 场模拟面试，录音回听；用 [[面试自检题库]] 逐题打分
- 每次面试后当天更新错题与项目 README（面试官问倒的点就是简历该补的点）
- 产出：≥ 2 场技术面试邀约 → 触及 [[目标与验收标准]] 的领先指标

## 每周固定节奏

| 周几 | 固定动作 |
| --- | --- |
| 周一–周五 | 每日 2 小时写代码 / 改项目，留 commit |
| 周六 | 30 分钟写复盘笔记，进本库 |
| 周日 | 10 分钟对照 [[目标反推校验记录]] 的复检规则打分、调整下周 |

## 什么情况下该改目标而不是改计划

- 第 4 周末仍没有 1 个公网可访问 Demo → 把「1–2 个月」延到 3 个月，别硬投
- 投 30 份 0 面试 → 问题在简历 / 选题，不在技术深度，停止学新东西两周
- 每周稳定投入 < 8 小时 → 承认时限不现实，改期限比降低验收标准诚实
