# Day 7 · 把 6 天的代码翻译成雇主听得懂的话

> 项目做得再对，简历写不出数字、面试答不上追问，等于没做。今天不写一行新功能代码。
> 注意：第 7 天你只有 **1 个**仓库 + 1 个 Demo，第 2 个在第 3–4 周，别硬凑。

## 45 分钟怎么分

| 时间 | 动作 |
| --- | --- |
| 0–20 | 用 [[简历项目描述模板]] 写 2 条描述（第 2 条可写「进行中」），每条含 ≥1 个能在仓库找到出处的数字 |
| 20–40 | 把 [[面试自检题库]] 8 题写成自己的话，每题 ≤5 行 |
| 40–45 | 合上笔记脱稿答 5 个核心题 + 跑 [[交付自检脚本]] + 阶段验收 |

## 完成标准（全勾才算过）

- [ ] 2 条简历描述各含 1 个可验证数字（引用 [[Day3_建评测集]] / [[Day4_单次可归因优化]] 的真实数据）
- [ ] 简历首屏放了 **1 个公开仓库 + 1 个 Demo 链接**（第 2 个仓库第 4 周补）
- [ ] 8 道题都有**自己写的**答案，不是复制的标准答案
- [ ] 脱稿能答出这 5 个：为什么不用 Dify / 怎么治理幻觉 / 怎么评估 RAG / 切片怎么定 / 工具调用失败怎么办
- [ ] `python check.py` 输出 **全部 PASS**（见 [[交付自检脚本]]）
- [ ] [[目标与验收标准]] 第 3 节「第 7 天末阶段门槛」逐条勾完
- [ ] 7 天打卡连续，每天都有 commit 或证据文件

**没全勾上就别进第 2 周** → 回到 [[目标反推校验记录]] 的「每周复检规则」，按固定动作补缺口。

## 今天最容易犯的两条（完整清单见 [[不做什么清单]]）

- ❌ 写「熟悉 / 了解 / 精通 / 深入研究了」这类形容词
- ❌ 把「熟练使用 Dify 搭建工作流」放在技能第一行（见 [[目标与验收标准]] 第 5 节）

## 卡住时的最短解法

| 卡点 | 处理 |
| --- | --- |
| 找不到数字 | 「评测集 20 条 / 拒答类 5 条 / 前后对比 1 次」也是数字，但必须真实 |
| 答不出「为什么不用 Dify」 | 口径：先用它做业务原型，再用手写链路换可控性、可评测性和异常兜底 |
| 8 题写不完 | 先写 5 个核心题，其余 3 题第 1 周补，打卡里标注 |
| `check.py` 有 FAIL | 按提示逐项补，不要改脚本让自己通过 |
