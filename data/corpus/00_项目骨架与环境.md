# 项目骨架与环境（Day 1 之前先做完这页）

> 这页只解决一个问题：**从哪下手**。目录建在哪、包装什么、key 放哪、每天代码写进哪个文件。
> 一次性约 20 分钟，**不计入 7 天 × 45 分钟**。做完这页，7 天里不再折腾环境。

## 一、项目 A 目录树（照建，别自创结构）

```text
llm-app-portfolio/
├── README.md
├── .gitignore
├── requirements.txt
├── .env.example
├── .env                 # 本地才有，绝不提交
├── data/corpus/         # 语料：复制本库 md 进来
├── ingest.py            # Day2 切片入库
├── query.py             # Day2 检索+生成（Day5 复用 search()）
├── tools.py             # Day5 两个工具
├── agent_loop.py        # Day5 手写分发循环
├── eval/
│   ├── cases.jsonl      # Day3 评测集
│   ├── eval.py          # Day3 一键评测
│   └── runs/            # 每次评测结果 before.json / after.json
├── app.py               # Day6 FastAPI
├── Dockerfile           # Day6
└── check.py             # 交付自检，见 [[交付自检脚本]]
```

**每个文件只干一件事**，这本身就是面试时能讲的结构设计。

## 二、一次性环境准备（约 20 分钟）

Git Bash 里执行（Windows 注意激活路径是 `Scripts` 不是 `bin`）：

```bash
python -m venv .venv
source .venv/Scripts/activate(Windows版:.\.venv\Scripts\Activate.ps1)
python -m pip install -U pip
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple openai chromadb fastapi uvicorn python-dotenv
python -c "import openai, chromadb, fastapi; print('env ok')"
```

最后一行必须打印 `env ok`，否则不要开始 Day1。

## 三、`.gitignore`（先写它，再写代码）

```text
.venv/
.env
__pycache__/
*.pyc
data/corpus/
eval/runs/
.chroma/
```

**为什么第一步就写**：key 一旦进了 commit，要改历史很麻烦，而且面试官会翻你的提交记录。这是唯一一个「顺序错了会出事」的步骤。

## 四、`requirements.txt`

```text
openai
chromadb
fastapi
uvicorn
python-dotenv
```

只这 5 个。装第 6 个之前先问自己：今天的完成标准用得到吗？用不到就不装（见 [[不做什么清单]]）。

## 五、`.env.example`：全项目统一这几个变量名

```text
LLM_API_KEY=sk-xxx
LLM_BASE_URL=https://api.example.com/v1
LLM_MODEL=填你的模型名
EMBED_MODEL=填你的 embedding 模型名
```

- 有云 API：填服务商给的 key / base_url / 模型名
- 没有 key 或网络不通：用本地 Ollama，`LLM_BASE_URL=http://localhost:11434/v1`、`LLM_API_KEY=ollama`、模型填 `ollama list` 里已有的名字
- **后面所有代码只读这 4 个变量**，不要在脚本里硬编码模型名——换模型只改 `.env`

## 六、语料怎么取（2 分钟，别去找数据集）

```bash
mkdir -p data/corpus
cp -Path "D:\仓库\ai知识库\10_目标\*.md" -Destination "data\corpus\"
cp -Path "D:\仓库\ai知识库\20_7天计划\*.md" -Destination "data\corpus\"
ls data/corpus | wc -l
```

预期 11 篇左右。用自己写的笔记当语料有三个好处：你天然知道正确答案（[[Day3_建评测集]] 出题不卡）、不用处理 PDF/表格、数据可以公开不怕泄露。

## 七、每天开工/收工两条命令

```bash
# 开工
source .venv/Scripts/activate
# 收工（必须做，否则当天不算完成）
git add -A && git commit -m "dayN: 一句话说明今天交付了什么"
```

## 八、7 天时间预算（合计 315 分钟，逐项核过）

| Day | 主要动作 | 预算 | 说明 |
| --- | --- | --- | --- |
| 1 | JD 采样 10 + 仓库/README 15 + smoke_test 15 + commit 5 | 45 | 骨架已给，只需填空 |
| 2 | 环境确认 5 + ingest 15 + query 20 + commit 5 | 45 | **已给骨架，实际是改参数**，见 [[Day2_手写最小RAG]] |
| 3 | 出题 15 + eval 20 + 写表 10 | 45 | 出题可用模板批量改 |
| 4 | 假设 10 + 改一处 20 + 重跑 10 + 写结论 5 | 45 | 只改一处，改完即停 |
| 5 | schema 10 + 循环 20 + 造 3 种失败 12 + 记录 3 | 45 | 骨架已给 |
| 6 | API 15 + Docker/文档 10 + 部署 13 + README 7 | 45 | 部署超 15 分钟就换穿透 |
| 7 | 简历 20 + 8 题 20 + 脱稿自测 5 | 45 | 不写新代码 |

**硬规则**：到点即停。没做完的按当天「卡住时的最短解法」降级，**不补进度、不熬夜**。7 天的目的是建立节奏，不是把项目做完。
